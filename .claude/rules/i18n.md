# Working on the translations (`i18n.js`)

Loaded by itself when `i18n.js` is opened. What may be translated at all (stored names never are) is in docs/languages.md.

- **Every new string goes into all three languages in the same commit.**

English, Українська and Svenska. `i18n.js` holds `UI[lang]` (all interface copy, keyed by dotted name), `EX[lang]` (the 41 built-in exercises as `[name, equipment, alternatives, note]`, in the same order as `DEFAULT_LIBRARY`) and `STD_EX[lang]` (the 71 strength-standards lifts, keyed by **slug** rather than by position, because that list is data the app doesn't own and a row in it could move). English lives in `UI.en`, in `DEFAULT_LIBRARY` and in `STD_EXERCISES` itself. `T("key", vars)` looks a string up and falls back to English then to the key, so a partial translation is always safe; `TN("day", n)` picks plural forms (one/other for en+sv, one/few/many for uk). Long copy carries its own `*bold*` and `_italic_`. **The markup is read off the TEMPLATE, before anything is put into it** (`T`): a username may hold underscores, and read the other way round `kerlit_the_dog` came out half in italics while a name with two asterisks grew a `<b style="…">` whose quotes ended any attribute it was printed in. What a person typed is text; only what a translator wrote is markup. That order is safe only because no placeholder has an underscore in its name, so keep it that way. **No em dashes (U+2014) in anything the app says**, in any language: a sentence that wants one is rephrased with a comma, a colon, a period or parentheses, never just has the character taken out, and in Ukrainian, where a dash is often grammar (it can stand in for the verb «є», or for any verb left out), the sentence is restructured instead (`є` with the instrumental, `якщо …`, a second clause). A standalone `"—"` that stands for an empty value or sits in a field as a placeholder is not punctuation and stays. The same rule holds for code comments, commit messages and every doc in this repo.
Adding or removing a language means editing `LANGS`, `LOCALES` and the matching `UI`/`EX`/`STD_EX` blocks. `resolveLang()` coerces anything not in `LANGS` to English, so a saved setting for a language that has since been dropped degrades quietly, and `migrate()` rewrites it on load.
