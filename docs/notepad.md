# The notepad

The Log tab's third mini tab, beside History and Calendar (the NOTEPAD block in `app.js`, below `renderLog`): notes kept the way Google Keep keeps them. Read this whole file before changing anything it describes, and update it in the same commit when that behaviour changes (CLAUDE.md, *Docs*).

- **WHAT IT IS** (`renderNotes` / `notesGridHTML` / `noteCard`, `renderNoteEditor`). A grid of cards in two balanced columns (`.pb-notes`), pinned ones under *Pinned* above *Others*, newest first. A note is words or a checklist (`list`, `items`), with a title, a colour and labels. A search field and a row of chips sit over the grid: *Notes*, *Archive*, *Trash*, and one chip per label in use (`noteLabelsAll`), which filters to that label. *Take a note…* and its checkbox make a text note or a list; on this tab the Log's + does too (`note-new`), since a + on a page of notes means a note, not a workout. A note opens full screen, tinted its colour, with pin and archive in its header and a tool bar at its foot: colour (`NOTE_COLORS`, `--note-*` tokens in `styles.css` for both themes, Keep's own palettes), *Show checkboxes* / *Hide checkboxes* (each line becomes a row, each row a line; ticks do not survive the trip to plain text), labels, when it was last edited, and a ⋮ sheet with *Make a copy*, *Send in a chat* and *Delete*.
- **THERE IS NO SAVE BUTTON, AND TYPING NEVER RENDERS** (`noteSet` with `draw` off, the `note.title` / `note.body` / `note.item` branch of `handleBind`). Keep saves as you type, so this does too: a keystroke writes the note straight into `state` and `persist()` is the checkpoint, so it syncs on the same debounce as everything else. `render()` rebuilds `#app` and the caret goes with it, which is the bug the chat search and the composer were both rewritten for (docs/chat.md), so the fields are never re-rendered under a finger. They grow to fit what is in them (`noteAutosize`), and `render()` sizes them (`noteFitAll`) BEFORE it puts the scroll back, or a long note is one line tall for a moment and the scroll is clamped. The tool bar is lifted over the on-screen keyboard by `--pb-kb`, as the chat composer is: it holds the controls a note is edited with, with the keyboard up.
- **A CHECKLIST IS TYPED LIKE A LIST** (`noteItemRow`, `noteSplitItem`, the keydown listener beside `handleBind`). Enter in a row makes the next row out of whatever was after the caret, draws it into the DOM beside the row and moves the caret into it, so the keyboard never goes down; a paste of several lines becomes several rows the same way. It is done off the newline the field RECEIVED rather than off keydown, because an Android keyboard often reports its keys as "Unidentified". Backspace at the very start of a row joins it onto the row above with the caret at the seam, as Keep does (keydown, which an Android keyboard does send for Backspace in an empty field). Ticking a row moves it under a collapsible *N ticked items* heading; the order inside `items` never changes, the two sections are drawn from it.
- **A NOTE COMES BACK WHERE IT WAS LEFT, AND OUT OF THE WAY WHEN IT SHOULD BE** (`snapshotDrafts` / `restoreDrafts`, `noteLeave`, `notesViewNow`). The open note is part of the crash snapshot (only its id: its words are already in `state.notes`), so a phone that kills the app mid-note opens back inside it, and a note that was still empty is dropped when it is then closed instead of sitting on the grid as *Empty note*. The editor sits under the conversation layer, so a chat notification tapped with a note open lands in the chat and Back returns to the note; the buttons in a chat card that lead elsewhere (open the notepad, the exercise, the day, the presets) and a timer notification close a note left open underneath (`noteLeave`, which also drops it if empty). A title is one line: Enter goes on to the note, as in Keep. A label view whose label has just left its last note falls back to *Notes*. The editor says when the note was last changed as a time today and a date before that (`noteWhen`).
- **NOTHING LEAVES ON A TIMER.** Archive takes a note off the grid (pinning an archived note brings it back, as in Keep); Delete puts it in the Trash, where it opens read-only with *Restore* and *Delete forever*, and *Empty trash* asks first. Keep empties its trash after seven days; this does not, because nothing in this app destroys what somebody wrote quietly (CLAUDE.md, *Principles*). The one exception is a note with nothing written in it, which is not kept when it is closed (`noteClose`, `noteEmpty`): it was never anything, so nothing is destroyed.
- **NOTES BELONG TO A PROFILE** (`state.notes`, migration v17, `notes` in `SYNC_COLLECTIONS` and in `COLLECTIONS` in `api/src/sync.js`). Like everything else that is not chat, so a note syncs between that profile's devices as a row of its own (`id` is the item id), rides in its backup, counts as content in `profileHasContent`, and another profile has its own notepad. Two people editing the same note between two syncs is the last push wins, the same honest non-answer docs/sync.md gives for a set. **A note's colour is a NAME from the palette, never a colour**, because it is printed into a style attribute: `cleanRow` holds it to `NOTE_COLOR_SET` (declared above `let state` for the reason `uid` gives) and holds labels and rows to their shapes; every word is escaped where it is drawn. On a profile shared read-only the notes can be opened and read (`note-open`, `note-close`, `notes-view`, `notes-q-clear` and `note-checked-toggle` are on `READ_OK`) and nothing else: the writing actions are not on it, and the fields are drawn read-only (`noteLocked`), since `handleBind` is not gated by `READ_OK`.
- **A NOTE GOES TO ANOTHER PROFILE THROUGH THE CHAT WITH YOURSELF** (kind `note`, `chatBuildThing` / `chatNoteOf` / `chatImport`, docs/chat.md). *Send in a chat* in the ⋮ sheet, or the composer's + (*Note*), sends a snapshot: words, rows and their ticks, colour and labels, not where it sat (pinned, archived). Added from the card, it lands at the top of the notepad of whichever profile is open, as a note of its own.
- **Not built, on purpose for now:** reminders (they would need the push machinery a rest timer uses), pictures and drawings in a note, sharing a note with another account as a live note (a snapshot in a chat is the sharing there is), and dragging notes into an order of your own (newest first stands in for Keep's default order).
